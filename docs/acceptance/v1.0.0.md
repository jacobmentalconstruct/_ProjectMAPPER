## Global stop conditions (section 15)

1. **Every UI operation maps to a shared action.** Met.
   [action-inventory.md](../action-inventory.md) lists each desktop operation and its
   action. [ui-map.md](../ui-map.md) lists every control, key binding, menu entry and
   close box, marks presentation-only ones, and names the test that drives each.
2. **Domain rules, state and approvals run without Tk.** Met.
   - `test_actions::test_headless_import`.
   - `test_acceptance_gaps::G1HeadlessExportTests`: scan, compile and export in a
     separate process that never imports `tkinter`.
   - Approvals go through the dispatcher's private resolver, not the UI
     ([developer-guide.md](../developer-guide.md)).
3. **Existing workflows, schemas, theme and linked controls are preserved.** Met.
   - The smoke tests (`test_ui_smoke`) and window tests drive every entry point.
   - The patch schemas are unchanged.
   - Layout changes are recorded in the decision log: action rows (8.2), log height and
     editor minimum width (8.4, 8.5).
4. **Stale plans, conflicting requests and denied approvals cannot mutate targets.** Met.
   - `test_actions`: approval required, forged flag rejected, approval re-checks external
     changes and the root generation, a duplicate request does not repeat a save.
   - `test_safety_regressions`: edit during approval, old preview, denied patch.
   - `test_error_wording::NamedEngineCodeTests`: a changed source on apply is refused and
     the file is kept.
5. **Write and recovery behaviour meets the byte-preservation and failure tests.** Met,
   with honest limits.
   - `test_patcher` preserves BOM and line endings.
   - `test_safety_regressions`: staging conflict, replacement failure, rollback that
     preserves an external edit.
   - `test_backup_integration`: recovery generations, and truthful recovery-store failures.
   - `test_acceptance_gaps::G4FailureInjectionTests`: read, chmod and cleanup failures.
   - Limits below.
6. **Snapshot freshness covers capture configuration as well as files.** Met.
   - `test_acceptance_gaps::G2FreshnessTests`: edits, additions and deletions.
   - `test_safety_regressions`: capture selection, capture option.
   - `test_exclusions`: rule changes block exports until the next compile.
   - `G3ExistingSnapshotTests`: stale, incompatible or corrupt snapshots are refused
     (defect D1 fixed).
7. **Per-file patch review, backup restore and retention, and event-backed history are

   - `test_project_review`, `test_project_review_window`, `test_review_views`.
   - `test_backups`, `test_backup_actions`, `test_backups_window`.
   - `test_history`, `test_history_window`.

## Defects found and fixed during final acceptance

- **D1:** a snapshot with an unsupported format version was accepted as current. Now
  refused (`stale_snapshot`).
- **D2:** a cleanup failure could mask the real error at five write sites. Cleanup
  never raises now.
- **D3** (test defect): a smoke test could open a real dialog and depended on keyboard
  focus. Smoke tests now fail on any unexpected dialog and call bindings directly.
- **D4:** a project apply refused for a changed source reported "Invalid request", and
  linked or `.parts` paths reported `invalid_input`. They now report `source_changed`
  and `unsafe_path`. This is a deliberate error-code change for 1.0.
- **D5:** the editor's **Keep backup** checkbox was squeezed at the minimum window
  width. The minimum now follows the toolbar.

## Owner decisions

- **E2:** the text editor offers Keep backup.
- **E3:** Windows is the tested platform; cross-platform CI is the first post-1.0 item.
- **E4:** the intermittent Tk start-up failure is explained by its trigger and eliminated
  from the suite.

All are recorded in the plan's decision log.

## Residual limitations

- **Platform:** tested only on Windows 10. macOS and Linux launch is untested.
- **Tk start-up under standard-handle swapping (E4):**
  - When the process's standard handles are swapped around Tk start-up, Tcl
    intermittently fails to read its library files. About 5 failures in 7,000 start-ups
    were measured, with no project code involved.
  - The suite avoids this with `--capture=sys`. The application never swaps these
    handles.
  - Not established: the Tcl-internal mechanism, and whether antivirus filtering takes
    part.
  - See [TODO.md](../TODO.md).
- **Two unexplained test-environment events,** recorded rather than explained:
  - one silent 3.10 run (Tranche 6): the process ended before its first test result
  - one layout-test failure in a `git archive` copy under load (Tranche 7)

  Neither has recurred in about 50 full runs on the final day.
- **Writes:** external races and crashes are handled honestly but cannot be prevented.
  - A file changed by another program between the last check and the replace can still
    be overwritten, within a narrow window.
  - A crash mid-apply leaves recovery material rather than a finished result.
  - A failed scratch cleanup can leave a `.patch-*` or `.projectmapper-*` file behind
    silently.
- **Layout:** measured at Tk scaling 1.33 only. The layout probe does not check rows
  inside the Exclusions window's scrolling list, which that window's own tests cover.
- **History** is per session, keeps 500 records and is not persisted.
- **Transport:** the action layer is in-process only. The CLI and MCP adapters are
  Phase 9.
- **Documentation:** a vendor export does not include `docs/`, so the README's links into
  `docs/` do not resolve in a vendor copy.
- **Static analysis:** pyflakes reports only notices for the existing `import *` sections
  ([TODO.md](../TODO.md)).
